# GitHub

GitHub is the platform I used to host Git repositories online. The distinction I learned is that **Git tracks changes and versions**, while **GitHub hosts repositories and provides tools for sharing and collaboration**.

## Repositories

A GitHub repository stores project files and their commit history. A repository can be public or private. I learned how a local repository can be connected to a remote one and how `git clone` can be used to copy an existing repository to a computer.

## Working with remote changes

The Git commands I practised connect the local project to its GitHub copy:

- `git push` sends local commits to the remote repository.
- `git pull` fetches remote changes and integrates them into the current branch.

This helped me understand that GitHub does not replace Git. It provides an online place to store and work with Git repositories.

## Collaboration

I explored a few GitHub features that support teamwork:

- **Branches** keep a set of changes separate from the main line of work.
- **Pull requests** provide a place to discuss and review proposed changes before merging them.
- **Issues** help record bugs, questions and tasks for a project.

## README and Markdown

A README is often the first file someone sees when opening a repository. I used Markdown to organise information with headings, lists, links and code blocks. Keeping it clear and up to date makes a project easier for others to understand.

## What I learned

I learned how Git and GitHub work together: Git manages the version history, while GitHub makes it easier to share that history and collaborate. A readable README and a sensible folder structure also make a repository easier to navigate.
